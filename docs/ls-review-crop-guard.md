# 审核裁剪框修改保护 v1.1.0

[安装 / 更新脚本](https://raw.githubusercontent.com/chengzi-1225/Insta360-chengzi/main/ls-review-crop-guard.user.js)。

## 安装

1. 用文本编辑器打开脚本文件，复制全部内容。
2. 在篡改猴中选择“添加新脚本”，替换默认内容，保存。
3. 刷新项目 10482 的审核页。左下角应出现“审核修改保护：已启用”。看到这个提示后再开始移动框。

脚本保护 `label.insta360.com` 下所有项目的审核中心，只在 `/review/workspaces/.../projects/...` 页面生效。标注中心 `/annotation/` 和其他网站不会启用。

## 使用与验收

移动一个裁剪框，再切换到另一个比例框。按钮应保持“修复并通过”；如果拦截了历史重置，左下角会显示“已保护 N 次”。

在本来就需要审核修改的任务上提交后，重新打开确认框仍处于修改后的位置。脚本不自动点击通过，也不发送独立的保存请求，继续使用平台原有审核流程。

如果看不到“已启用”，或出现红色“未启用”，不要把脚本当作已经生效。如果按钮仍退回“通过”，先不要提交，保留现场排查。

## 能力边界

- 保护安装并生效后产生的修改历史，保留撤销、重做以及待执行的自动保存。
- 保留图片预览和模板中的比例锁定。
- 不修改项目配置、标注标签、现有坐标或审核结果；不把所有任务强制标成已修改。
- 已经丢失的历史不能由此恢复。安装后先刷新页面，再重新调整需要修改的框。
- 停用或删除脚本后刷新页面，即恢复平台原有行为。

## 验证记录

基于线上观察到的调用链，使用与线上相同版本的 MobX State Tree 3.17.3 和 MobX 5.15.7 复现历史重置与审核提交条件。无补丁时，移动后调用 `reinitHistory(false)` 会得到 `isDirty: false, result: null`；加入补丁后保留修改后的坐标与修改标志。

本地测试覆盖预览初始化、连续切换、撤销重做、正常重置、切换标注、切换项目、替换编辑器、重复安装、卸载和不兼容状态。

另在项目 10482 当前审核页做了接入检查：根对象中间件接口存在，临时拦截 `reinitHistory(false)` 一次成功，检查前后序列化坐标一致，未生成修改或草稿。临时检查已移除，未将脚本永久安装到浏览器。

本地复现测试不能替代生产页面上“提交后重新打开”的完整验收。尚未完成真实审核提交后的完整验收。

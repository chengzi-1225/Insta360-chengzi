# Regions 直接清空并提交 v3.2.3

[安装 / 更新](https://raw.githubusercontent.com/chengzi-1225/Insta360-chengzi/main/label-studio-regions-clear-submit.user.js)

基于用户提供的 v3.2.0 修改，已删除“预览任务”“核对快照”和预览表格二次勾选。保留同一名称和 namespace，安装时可覆盖原来的 Regions 脚本；自动更新地址固定。

## 使用

1. 停止正在运行的旧脚本并等当前任务结束，再安装更新、刷新项目数据页。
2. 打开“Regions 清空并提交 v3”，输入任务 ID，或点击“导入页面勾选 / 全选”。也可以填入当前打开任务。
3. 点击“直接清空并提交”，确认项目和任务数量后立即逐条处理，无需先预览。
4. 查看每条任务的执行进度；结束后可下载执行记录，再刷新列表核对结果。

ID 支持逗号、换行、分号分隔，以及井号前缀；重复 ID 自动合并，每批最多 10000 个。执行范围为确认时输入框中的 ID。确认后输入框的修改只用于下一次执行。

## 清理和提交方式

每条有轨迹的任务按原脚本的原生编辑器流程：打开任务 → 等待历史和媒体加载完成 → 读取默认选中的标注 → 删除全部 reframe 轨迹及相连关系 → Ctrl+Enter 提交 → 等待重新加载 → 从服务器回读提交内容。脚本逐条完成后进入下一条，不会先把所有任务打开一遍。

提交发到平台父页面，不发送到面板输入框；不再查找或点击提交按钮。Mac 上平台默认绑定 Command+Enter，脚本把本次生成的 Ctrl+Enter 临时接到相同的原生提交或更新动作，不改动实际键盘快捷键。平台快捷键需开启；保留提交成功事件、30 秒超时和服务器回读验证，不自动补点或重复提交。

成功条件是已收到原生提交成功事件、服务器中该标注结果与清理后的预期一致、reframe 轨迹为 0、任务状态为 `ANNOTATED`（已提交）。当前标注没有轨迹时跳过，避免重复提交。遇到只读、内容变化、原生校验拦截、提交超时或回读不一致时停止，不自动重试提交。

本版沿用提供脚本的处理范围：清理默认标注中的 Regions，保留视频级分类、其他标注版本和机器预测原始记录。它完成后是“已提交”，不是把任务恢复待标注的旧版 API 工具。脚本不要求下载备份。

## v3.2.3 提速与跳过

- 当前任务提交时，最多提前只读获取下一条任务数据，减少任务之间的读取等待。原生编辑器仍按顺序清空和提交。
- 已有标注，且所有标注版本、草稿、预测均明确没有 reframe 时，再次读取确认后直接跳过，不加载该任务视频。数据结构不明、当前打开任务或新任务仍进入原生编辑器检查；不会仅凭某一个版本为空就跳过。
- 下一任务的预取失败时，在对应任务开始前停止；预取只读取，不提前清空或提交。

此前 v3.2.2 的优化继续保留：

- 同一次加载的连续核查复用已经满足的稳定等待。原生请求、标注来源、草稿来源或实际结果一旦变化，重新等待完整的 1.5 秒稳定窗口。
- 等待原生历史和媒体加载时，同时读取服务器任务；提交成功后，原生重新加载与服务器回读也同时进行。
- 回读内容已经匹配时直接用于最终验证；如果后台状态尚未更新，加载结束后补一次只读核查，不重复提交。
- 原生请求未结束、媒体未就绪或草稿仍在保存时，减少不必要的完整标注序列化。

稳定内容下，两次连续稳定检查的本地模拟等待从 3000ms 降为 1500ms。此数字只衡量重复等待，不代表整个任务耗时或真实项目加速倍数。整体速度仍取决于视频、历史数据加载和平台提交响应；仍按单一原生编辑器逐任务提交。

## 停止与记录

“当前任务完成后停止”会让当前执行中的任务完成清空、提交和回查，然后停止后续任务；已经提交的清空不会自动恢复。若当前步骤失败，立即停止后续步骤和任务。

界面表格最多显示当前位置附近 300 个任务，以控制大批量时的页面开销；下载执行记录包含全部已开始任务及失败阶段、提交标注 ID。尚未开始的任务数量会单独显示。

## 验证

30 项本地模拟测试通过，覆盖 Ctrl+Enter 键值、Mac 单次原生动作、所有版本无轨迹判定、下一任务只读预取、预取失败停止，以及原有清空提交顺序、空轨迹跳过、停止行为、失败拦截、分类保留、无预览确认、稳定等待和服务器回读验证。尚未在真实项目执行本修改版；实际速度取决于平台和视频响应。

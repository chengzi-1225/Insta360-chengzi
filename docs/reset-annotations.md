# 清空标注并恢复待标注 v1.0.5

[安装 / 更新最新版](https://raw.githubusercontent.com/chengzi-1225/Insta360-chengzi/main/label-studio-reset-annotations.user.js)

安装后油猴会按固定地址检查更新，也可以点击工具底部“安装 / 更新”。先停止旧版运行并等待当前请求回查结束，再覆盖安装、刷新项目列表；面板底部应显示 v1.0.5，请勿同时启用多个副本。

## 直接清理，无需整批预览

1. 勾选任务，点击“读取已勾选任务”，或直接输入任务 ID。
2. 点击“直接清空（无需预览）”，确认项目和任务数量后开始。
3. 直接模式优先每 100 个任务调用平台批量清理，读取与核查最多 8 个任务并行，批量写入依次执行。每批完成后继续下一批，不等待几千个任务全部预览。平台未提供 Delete Annotations 和 Delete Predictions 时，沿用最多 3 个任务并行的逐条方式；预览后执行也保留严格的逐条比较。

“预览范围”和“下载备份”均为可选操作。下载备份需要先预览以取得完整数据；未下载本次备份时删除弹确认，取消则不读取任务内容、不删除；已下载本次完整备份时直接执行，不重复弹窗。下载备份本身不弹确认。

每个任务写入前仍会保存浏览器本机备份；保存失败则停止。可以“导出本机备份”。备份仅包含接口返回的任务、标注、草稿和预标注，不保证包含完整的后台审核评分历史，也没有自动恢复功能。

## 批量删除和独立核查

每批先备份、核对内容，再按审核评分、验收、审核员、标注员、标注及草稿、预标注的顺序执行账号支持的原生动作。批量请求只包含文本框中本批最多 100 个明确 ID，绝不调用 Delete Tasks 或整个项目全选。即使任务详情计数为 0，原生内容清理仍会执行，避免详情漏报导致跳过。

除任务详情和独立草稿列表外，新版还读取 `/api/tasks/{id}/annotations/` 独立标注列表，并与详情合并。部分平台该列表不包含跳过记录，因此详情返回的跳过记录也会保留用于核查和备份。任务详情返回空数组、独立列表却仍有标注时，不会显示完成。接口不支持该核查、数量异常、存在剩余内容或状态未恢复时，显示失败或待核实。

新增“核查是否清空”：输入原来的任务 ID 后点击，只读取服务器当前数量，不发出删除、不沿用上次完成结果。日志逐任务显示标注、草稿、预标注数量；导出执行结果的 `verification` 保存回查时间、剩余记录 ID 和状态。界面仅显示最近 300 行，完整执行结果仍可导出。

批量标注或预标注返回后台任务时，只读轮询剩余任务，最多约两分钟并受请求耗时影响；确认内容为空后才继续后续动作和批次。审核或人员关联的后台操作无法仅凭标注数量确认，显示待核实并暂停。任何后台动作均不重复提交。

如旧版显示完成，刷新后编辑器仍有轨迹，先更新新版并使用“核查是否清空”。若独立核查与编辑器依然不一致，导出该任务的“接口诊断”继续排查；不能仅凭本地模拟测试断言真实项目的问题已解决。诊断包含详情与独立标注列表数量及记录 ID，不包含标注答案和视频地址。

## 平台原生关联清理

脚本接入列表菜单中的原生删除动作，优先清理关联记录，再删除标注、草稿和预标注，最后核查待标注状态。只执行当前账号实际返回且未禁用的动作：

- Delete Reviews and Scores / Delete Reviews：审核及平台该动作负责的评分记录。
- Delete Acceptances：验收记录。
- Delete Reviewers：平台对应的审核员关联。
- Delete Annotators：平台对应的标注员关联。

动作顺序为审核评分、验收、审核员、标注员。所有请求明确指定当前项目和本批明确任务 ID；逐条模式只含单个 ID。不使用“整个项目全选”，不附加可能扩大范围的视图参数。任务本身、视频及原始数据保留。不会选择 Delete Tasks，也不会自动提交“批量任务状态转换”。单独转换状态不等于审核评分记录已被删除。

脚本从 `/api/dm/actions/` 读取实际动作和表单信息；不会猜测私有撤销接口。已知人员筛选表单使用“所有人”；未知表单字段会停止并提示诊断。人员清理动作未提供时，不宣称对应人员关联已清空。

原生操作记录保存在导出结果的 `nativeActions`，本次可用操作在 `nativeActionsAvailable`。批量操作的 `scope: batch` 及 `taskIds` 标明作用范围，`processed_items` 是整批返回数量，不能当作每个任务的数量；每任务实际消失的记录 ID 在 `removed`。后台任务按上文核查，不把“已接受”当作“已完成”。真实项目还需要验证当前账号的动作与权限。

## 失败、停止与核查

- HTTP 422“已经审核并打分，不能直接删除”：平台仍拒绝删除。查看原生动作结果及账号权限，或联系管理员；没有确认删除任何记录时为失败，已经执行部分清理则为部分完成。
- 预览后 `annotations[id=...].state` 或实际内容变化：预览模式停止删除，日志展示变化前后值；直接模式以每个任务开始执行时读取的数据为基准，备份后再核查。
- 原生审核清理导致的审核状态、评分及人员字段变化可以接受，实际 `result`、源数据、记录 ID 和其他内容变化仍会中断。
- 一个任务触发批次停止时：未写入的任务显示“已停止”；已删除过记录的任务显示“部分完成”，日志列出类型、数量和 ID；同时列出触发任务与原因。未派发的任务计入“未开始”。
- 不确定的请求会回查，不盲目重发删除。本机备份可以导出，已删记录不会自动恢复。
- 点击停止后：已清除的内容不会恢复；已提交的整批最多 100 个任务仍可能完成。脚本回查这批结果后停止后续写入，未开始的批次保持不动。后台任务可能在停止后继续执行，请稍后独立核查。

遇到接口兼容问题，输入目标 ID，点击“导出接口诊断”。只读取首个任务的字段结构、OPTIONS 及当前原生动作列表，不执行修改。不要把真实诊断或备份上传到公开仓库。

## v1.0.5

- 直接模式每 100 个任务调用平台原生批量清理，读取最多 8 个任务并行；205 个含标注任务的模拟用例共 9 次批量写入。

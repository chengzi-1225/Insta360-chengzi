# 清空标注并恢复待标注 v1.0.4

[安装 / 更新最新版](https://raw.githubusercontent.com/chengzi-1225/Insta360-chengzi/main/label-studio-reset-annotations.user.js)

安装后油猴会按固定地址检查更新，也可以点击工具底部“安装 / 更新”。覆盖安装后刷新项目列表，面板底部应显示 v1.0.4，请勿同时启用多个副本。

## 直接清理，无需整批预览

1. 勾选任务，点击“读取已勾选任务”，或直接输入任务 ID。
2. 点击“直接清空（无需预览）”，确认项目和任务数量后开始。
3. 脚本最多同时处理 3 个任务，逐个读取、清理并回查，不等待几千个任务全部预览完成。

“预览范围”和“下载备份”均为可选操作。下载备份需要先预览以取得完整数据；未下载本次备份时删除弹确认，取消则不读取任务内容、不删除；已下载本次完整备份时直接执行，不重复弹窗。下载备份本身不弹确认。

每个任务写入前仍会保存浏览器本机备份；保存失败则停止。可以“导出本机备份”。备份仅包含接口返回的任务、标注、草稿和预标注，不保证包含完整的后台审核评分历史，也没有自动恢复功能。

## 平台原生关联清理

v1.0.4 接入列表菜单中的原生删除动作，优先清理关联记录，再删除标注、草稿和预标注，最后核查待标注状态。只执行当前账号实际返回且未禁用的动作：

- Delete Reviews and Scores / Delete Reviews：审核及平台该动作负责的评分记录。
- Delete Acceptances：验收记录。
- Delete Reviewers：平台对应的审核员关联。
- Delete Annotators：平台对应的标注员关联。

动作顺序为审核评分、验收、审核员、标注员。所有请求明确指定当前项目和单个任务 ID，不使用“整个项目全选”，不附加可能扩大范围的视图参数。任务本身、视频及原始数据保留。不会选择 Delete Tasks，也不会自动提交“批量任务状态转换”。单独转换状态不等于审核评分记录已被删除。

脚本从 `/api/dm/actions/` 读取实际动作和表单信息；不会猜测私有撤销接口。已知人员筛选表单使用“所有人”；未知表单字段会停止并提示诊断。人员清理动作未提供时，不宣称对应人员关联已清空。

原生操作记录保存在导出结果的 `nativeActions`，本次可用操作在 `nativeActionsAvailable`。平台返回后台任务时显示“待核实”并停止，不重复提交，也不把“已接受”当作“已完成”。真实项目还需要验证当前账号的动作与权限。

## 失败、停止与核查

- HTTP 422“已经审核并打分，不能直接删除”：平台仍拒绝删除。查看原生动作结果及账号权限，或联系管理员；没有确认删除任何记录时为失败，已经执行部分清理则为部分完成。
- 预览后 `annotations[id=...].state` 或实际内容变化：预览模式停止删除，日志展示变化前后值；直接模式以每个任务开始执行时读取的数据为基准，备份后再核查。
- 原生审核清理导致的审核状态、评分及人员字段变化可以接受，实际 `result`、源数据、记录 ID 和其他内容变化仍会中断。
- 一个任务触发批次停止时：未写入的任务显示“已停止”；已删除过记录的任务显示“部分完成”，日志列出类型、数量和 ID；同时列出触发任务与原因。未派发的任务计入“未开始”。
- 不确定的请求会回查，不盲目重发删除。本机备份可以导出，已删记录不会自动恢复。

遇到接口兼容问题，输入目标 ID，点击“导出接口诊断”。只读取首个任务的字段结构、OPTIONS 及当前原生动作列表，不执行修改。不要把真实诊断或备份上传到公开仓库。

## v1.0.4

- 输入 ID 可以直接执行，整批预览可选。
- 接入平台原生审核评分、验收及人员关联删除动作。
- 区分未写入停止、部分清理及后台任务待核实，记录触发任务和实际已删除清单。
- 测试页面可模拟“已审核打分 → 原生清理 → 标注删除”和缺少原生动作时的 422。

## 历史改进

v1.0.3 改用平台原生跨页选择，支持完整 ID 列表和全选筛选结果。保留筛选与排除项，分页核对总数；6000 条勾选不再只读取可见的 24 行。备份下载可选，未下载删除弹确认；增加状态前后值和只读诊断。

v1.0.2 移除人工确认勾选框，增加 GitHub 固定更新链接；最多 3 个任务并行，复用每次删除后的核查结果，减少重复读取。同一任务内顺序清理并回查。
